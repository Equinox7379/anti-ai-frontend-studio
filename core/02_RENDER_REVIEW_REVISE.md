# 渲染、双通道批评与实际修正

第一稿不是结论，真实渲染才是证据。设计说明、规范通过和源码整洁都不能替代浏览器里的结果。

## 1. 固定真实条件

至少固定：

```text
路由／URL
数据与用户权限
视口和浏览器缩放
主题与字体加载
loading 结束条件
滚动位置
```

全面设计通常查看一个代表桌面、一个代表移动和一个高风险状态；局部任务只看受影响视口，不制造截图工程。

## 2. A 通道必须先完成

在不知道检测结果和 AI 特征命中的情况下，先做：

- 3 秒身份与第一主角；
- 30 秒对象、结果、形成关系、验证和下一步；
- 一次真实操作路径；
- 设计特异性、层级、情绪、认知负荷和产品真实性判断；
- 2—3 个强项与 3—5 个优先问题。

先保存 A 的文字记录。若先看到 detector，再形成审美意见，就失去无锚定价值。

## 3. B 通道只收集事实

A 完成后再运行：

```text
node tools/slop_detector.mjs <实际 UI 源码目录> --json
```

并检查 computed style、几何、状态、横向溢出、触控、焦点、字体、相同状态截图和高风险组合。B 只报告源码与浏览器事实、置信度及可能误报，不评价“优秀不优秀”。

检测器零命中只是机械下限；单个命中也不能自动定罪。

## 4. 综合，而不是拼接

记录：

```text
A 与 B 一致：
A 发现、B 无法检测：
B 发现、A 漏看：
B 的假阳性或合法例外：
仍未知：
```

设计评审负责特异性、任务、情绪与层级；确定性通道负责可定位实现事实。两者不得互相替代，也不得合并成一个生成者自评分。

## 5. 修正优先级

```text
任务受阻、数据或状态误导
→ 信息架构与主关系
→ 层级、密度和响应式
→ 字体、表面、颜色与动效
→ 光学和代码精修
```

发现真实问题后修改实际代码并重新渲染相同状态。检测器提示但经页面语义证明合理的内容，不必为了清零而删除。

## 6. 防退化

- M-A：不要把规则上限当使用配额。
- M-B：参考必须迁移任务关系，不只搬皮肤。
- M-C：不要用漂亮反思软化用户明确否定。
- M-D：不要在首稿前用反模式清单定义构图。

## 7. 结束条件

至少解决最重要的真实问题，并记录：

```text
PRIORITY_PROBLEM
ROOT_CAUSE
CODE_CHANGE
RENDERED_RESULT
PRESERVED_STRENGTH
UNVERIFIED
```

若第一稿确实成立，不为表演迭代强造变化；但必须有真实渲染和任务路径证据。不得输出自签设计分。
