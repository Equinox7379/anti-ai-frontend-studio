# 设计负责人核心：从灵感到优秀作品

## 1. 成功标准

“没有 AI 味”只是质量地板。优秀作品同时满足六层：

```text
清楚：用户立刻知道这是哪里、主要对象是什么、下一步是什么。
连贯：信息、状态、动作、视觉语法和响应式属于同一个系统。
特异：结构由这个产品的任务与关系产生，换行业后不能无损复用。
确信：设计作出了少量明确取舍，不是所有元素平均正确。
精工：字体、数字、间距、对齐、状态、内容边界和浏览器表面经得起使用。
克制的愉悦：有恰当的人格与记忆，但不靠效果堆积。
```

反 AI 不是把所有页面做成白底、黑字、细线和零圆角。设计的目标是用最合适的形式帮助真实的人完成真实任务。

## 2. 先解释灵感，不要照字面配色

把用户输入拆成四层：

| 层 | 要回答的问题 | 示例 |
|---|---|---|
| 事实层 | 产品、用户、数据、平台、已有资产是什么 | 税务工作台；长时间桌面使用；大量金额与政策依据 |
| 感受层 | 用户希望感到什么、拒绝什么 | 安静可信，但不能像政企内网；有力量但不炫技 |
| 功能层 | 这种感受必须怎样改变操作或理解 | 结果必须可追溯；计算关系不能被卡片切断 |
| 技术层 | 哪些限制会改变实现 | 中文、Windows、离线、390px、无远程字体 |

不要把情绪词直接翻译为某个字体类别、明暗主题、色板或分栏习惯。形容词只有转化为可观察的任务后果才有设计价值。

## 3. 建立页面真相

动手前，用简短文字确认：

```text
USER：谁在什么环境中使用？
JOB：这一屏最重要的动作或理解是什么？
PRIMARY_OBJECT：用户正在处理的核心对象是什么？
CONSEQUENCE：出错、误读或延迟的代价是什么？
CONTENT：真实内容长度、数字、语言和状态有哪些？
INCUMBENT：现有系统中哪些资产、交互和心智模型必须继承？
```

已有项目先审计再设计。保留正常工作的结构、术语和组件；不要为了展示新风格制造无关改版。

## 4. 选择界面模式

一个页面可以混合，但必须有主模式：

- **Operate**：完成任务、录入、判断、审批、分析。稳定与效率优先。
- **Read**：理解长内容、课程、法规、报告。节奏与阅读优先。
- **Persuade**：解释价值、建立信任、促成行动。叙事与证据优先。
- **Experience**：品牌、文化、活动、作品。感受与记忆优先。

操作型页面不应被营销 Hero 接管；体验型页面也不必伪装成无性格后台。

## 5. 写出屏幕命题

用一句话完成：

> 用户进入这一屏，最需要【理解／比较／完成／确认】什么？

好的命题能组织全页。例如：

```text
统计结果页：估计是多少、是否可信、在哪些条件下失效、如何复现。
税务底稿：税额怎样从会计利润经过调整形成，每一步依据什么。
审计训练：结论在哪条“认定—风险—程序—证据”链上成立或断裂。
```

页面可以有多个模块，但只能有一个主命题。其他内容必须支持、质疑、限制、解释或追溯它。

## 6. 识别主信息关系

优先判断关系，而不是组件：

| 关系 | 常见任务 | 首选表达 |
|---|---|---|
| 顺序 sequence | 步骤、向导、学习路径 | 连续推进、当前阶段、可恢复位置 |
| 比较 comparison | 方案、记录、前后差异 | 共享尺度、对齐矩阵、并列事实 |
| 层级 hierarchy | 目录、树、分类 | 缩进、分组、展开、面包屑 |
| 证据 evidence | 结论、来源、版本 | 引用、追溯路径、就地依据 |
| 因果 causality | 输入、调整、结果 | 连续链、公式、过程解释 |
| 集合 collection | 项目、记录、资产 | 列表、表格、画廊；由比较任务决定 |
| 时间 time | 进度、版本、事件 | 时间线、状态变化、关键节点 |
| 编辑 editing | 草稿、表单、文档 | 输入—校验—保存—恢复 |
| 监控 monitoring | 队列、告警、诊断 | 异常优先、趋势、处置入口 |
| 网络 network | 依赖、引用、关联 | 节点、路径、邻接关系 |
| 空间 spatial | 地图、布局、位置 | 坐标、区域、距离、方向 |

例如连续计算不应自动拆成六张卡；真正独立的项目、证据面板或复现信息可以拥有独立边界。

## 7. 熟悉性下限与特异性上限

基础交互要熟悉：按钮像按钮、表单可预测、返回可找到、状态可理解。差异不来自随机错位、隐藏导航或自定义光标，而来自：

- 领域对象如何组织；
- 关系如何可视化；
- 用户如何验证结果；
- 失败如何恢复；
- 内容密度如何随任务变化；
- 品牌与真实工作环境如何进入系统。

“看起来与众不同”不能以破坏理解为代价；“符合行业习惯”也不能变成套一个 Dashboard 骨架。

## 8. 参考只迁移因果原则

需要参考时，最多让当前方向承担三种角色：

```text
工作流参考：对象、状态、动作和后果相似。
交互参考：信息拓扑、输入方式或恢复路径相似。
表达参考：只借一个有限的节奏、材质或排版原则。
```

每项参考必须写成：

```text
因为【真实关系】，参考采用【机制】，使用户能够【结果】。
本项目迁移【原则】，不复制【字体、色值、品牌、骨架、动效】。
```

产品工作流优先看成熟产品和官方系统。Awwwards、作品集和活动页只可有限用于表达，不得定义数据、表单、权限和错误流程。搜索排名或工具推荐只是候选，不能替你裁决。

五轴／卡库只在结构已经成立、第一方向过于安全时，作为**单轴扰动器**：一次只改变一个轴并观察代价；不得把多个品牌的布局、字体、颜色和动效拼成所谓“原创”。

## 9. 探索数量由不确定度决定

- 局部修正或方向明确：一套方向，做变量对照。
- 存在两条真实任务路径：两套结构。
- 产品仍模糊：最多三套，必须改变主工作区、信息顺序或交互路径。

不要为了合规生成正好三套；也不要把多套方案平均混合。每套必须说明它更擅长什么、牺牲什么。

## 10. 从项目自身建立视觉世界

艺术指导优先从五个来源提取：

```text
已有品牌资产
领域物件与文本
数据行为
真实使用环境
平台与设备限制
```

例如统计结果页可以从“估计—不确定性—证据—边界—复现”形成构图；税务底稿可以从“来源—调整—派生—合计—依据”形成结构。不要先搜索“统计网站风格”或“税务高级配色”。

## 11. 功能性焦点机制

页面通常需要一个主导机制，但它不是强制配额。只有当它真实提升理解、操作、验证或记忆时才使用。

可能的机制：

- 因果链中的连续公式；
- 结论与证据之间的可追溯路径；
- 共享尺度的差异矩阵；
- 同位显影；
- 错误发生位置的判断链；
- 当前结果与适用边界的联动；
- 多视图切换时保持同一对象心智模型。

验证问题：去掉装饰和专业文案后，这个机制是否仍改变用户的阅读或操作？若否，它只是 Signature 表演。

## 12. 构图与对比预算

先安排重量，再选择装饰：

```text
PRIMARY_FOCUS：全页唯一主角。
SECONDARY_SUPPORT：解释、限制、质疑或操作。
QUIET_ZONES：主动退后的元数据、版本和低频操作。
DENSITY_ARC：页面何处紧、何处松、何处停顿。
```

对比可来自尺度、位置、空间、表面、颜色、字体和动效。通常只让一至三项承担主要差异；所有维度同时拉满会变成噪声，全部接近则平淡。

“只 Bold 一个地方”是删减原则，不是必须制造一个巨型方块。一个高密度产品也可以靠精准比较和异常优先形成确信感。

## 13. 矩形与表面纪律

矩形不是原罪，**用同一种矩形替代所有关系**才是卡片墙。

按以下顺序解决分组：

```text
内容顺序
→ 邻近与留白
→ 共享对齐和基线
→ 字号、字重与数字格式
→ 缩进、列表、表格、行内展开
→ 局部规则线或背景平面
→ 完整有界表面
→ 高程与浮层
```

只有上一层不足时才升级。完整表面应对应独立对象、独立状态、独立操作、不同阅读模式或需要保护焦点的边界。同级比较对象可以重复容器；连续因果和顺序不应被切成一排盒子。

不要把“允许最多几个表面”当作必须用满的配额。每个主要表面写出唯一职责，写不出就拆掉边界。

## 14. 字体是信息与人格，不是字体名

先定义角色：UI、连续阅读、数据、展示、标识。项目可以只有一个家族；不要为了显得设计过而强配两套字体。

中文项目按 CJK-first 决定：

- 中文字面率、标点重心、实际可用字重；
- 与数字、英文、版本号的基线；
- 金额小数点、括号负数、百分号；
- Windows／Android 等目标平台栅格化；
- 字体加载失败时的布局变化。

字体性格由一组参数共同形成：

```text
字形家族、字号、字重、字宽、字距、行高、数字特性、换行、角色间对比。
```

未经判断的流行无衬线＋展示衬线搭配，以及只换一个冷门字体名，都是高风险自动人格。操作／阅读型产品优先稳定和扫描；展示字体只有在品牌、出版或体验任务确有依据时使用。

## 15. 色彩、材质、图标与动效

颜色先分职责：画布、正文、交互、状态、数据、品牌。不要让同一绿色同时代表链接、成功、当前项和装饰。低对比不是高级。

材质必须解释空间或品牌事实。渐变、玻璃、噪点、阴影和纹理不是“提升质感”的默认按钮。

图标要有一致家族、重量和基线；没有必要就不放。换一个更冷门图标库不等于原创。

动效先服务状态连续性。普通 hover、focus、loading 是交互语法；作者性动效通常只保留一个真正有任务含义的时刻，并为 reduced motion 提供等价路径。不要全页排队飞入。

## 16. 响应式是重组任务

移动端不等于把桌面列纵向堆成卡片。重新回答：

- 手机上用户最先需要什么？
- 哪些比较必须保持共享尺度？
- 桌面辅助栏应变成就地展开、抽屉还是下一步？
- 低频元数据何时折叠？
- 触控、键盘、长中文和系统缩放是否成立？

桌面和移动可以不同构图，但必须保存同一业务关系。

## 17. 第一版必须是真实作品

使用真实或结构等价内容，至少覆盖：

```text
普通中文
超长中文标题
金额／日期／版本号
零值或缺失值
空状态
错误或不可用状态
主要交互
```

有现有代码时直接在项目中实现；无仓库时建立可运行原型。第一版不是展示意图的静态海报，而是可被浏览器检查的工作表面。

把下列内容写入简短的 `PROJECT_DESIGN.md`，不要等待用户逐项批准：

```text
页面命题
主要用户任务与对象
主信息关系
保留的现有资产
选定结构及放弃的真实替代
功能性焦点（若有）
构图重量与安静区
字体角色与实际参数方向
表面、颜色、动效职责
桌面与移动结构
最大风险和验证方式
```

## 18. 改版任务先审计，再决定改多少

现有项目不要从空白风格词开始。先读取代表页面、相邻流程、共用 Token、组件、真实状态和技术栈，区分：

```text
必须保留的产品事实与心智模型
已经成立的视觉语言
局部实现缺陷
信息架构或层级不匹配
真正的模板化默认
```

修复应发生在最窄的正确层级。局部缺陷不升级为重品牌；方向错误也不能靠精修掩盖。不要为了展示新设计而迁移框架、组件库或整个视觉世界。

## 19. 长期产品事实与本页策略分开

多页面或长期项目可以使用 `templates/PRODUCT_CONTEXT.template.md` 保存用户、任务、对象、术语、证据、平台和长期约束。它不记录本页色板、布局或视觉概念。

每个具体页面仍由 `PROJECT_DESIGN.md` 记录本页命题、中心关系、构图、字体、状态和响应式。单页任务不需要多维护一个文件。

## 20. 设计动词只用于已有方向

用户后续说“再大胆点”“收一点”“润一下”“换个说法”时，读取根目录 `DESIGN_VERBS.md`。一次只处理一个明确目标，并保持未命名区域、既有行为和视觉世界不变。设计动词不能替代初始方向，也不能成为添加新字体、颜色和特效的许可证。
