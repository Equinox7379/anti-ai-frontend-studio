Read the package root `00_READ_FIRST.md`. When multi-file retrieval is unreliable, read `ONE_FILE_MODE.md` in full. Own the design and implementation work available in the current environment. Do not stop at advice, do not ask the user to select routine design axes, and do not load anti-pattern materials before an actual first render exists.

For an existing project, audit the incumbent product, stack, tokens, states and neighboring flows before changing the visual world. For a long-lived multi-page product, use `templates/PRODUCT_CONTEXT.template.md` only when durable cross-surface truth is genuinely useful.

Required outcome: derive a task-specific page thesis and information relationship, implement an actual page, render desktop and mobile, save an unanchored Assessment A before running the descriptive detector, synthesize Assessment A with deterministic/browser evidence, revise real code, and deliver concise evidence without self-scoring.

Use `DESIGN_VERBS.md` only for bounded follow-up changes to an existing direction. A detector finding is evidence to review, never proof of poor design; a clean detector is never proof of quality.
