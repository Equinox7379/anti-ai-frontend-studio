# 从 353 个成熟参考中得到的设计结论

## 1. 成熟设计没有一套共同皮肤

样本中同时存在纯黑白、两色系统、强色、低饱和、摄影主导、3D、编辑排版、密集表格、公共服务表单和无样式原语。任何人试图从这些案例归纳出“成熟网站统一使用某字体、某圆角或某背景”，都会再次制造模板。

## 2. 产品表面与表达表面必须分开

Carbon、Material 和其他成熟系统都以不同方式区分任务型与表达型时刻。产品工作区需要速度、错误恢复、状态与密度；品牌页面可以牺牲部分效率换取叙事和记忆。高级感来自模式切换有边界，而不是把大标题、滚动动画和低密度扩散到所有页面。

## 3. 获奖站是表达实验室，不是产品行为标准

Razorpay Sprint 以百余次交互承载百余项更新，Cartier 使用产品页、音频与沉浸滚动，Mouthful of Dust 使用实时 3D。它们的表达与主题高度绑定。把这些手段直接搬到会计底稿、课程阅读或项目列表中，只会制造另一种 AI 展示站。

## 4. 真正可迁移的是关系，不是外观

Wise Currency Converter 值得学习的是金额、币种、汇率和结果处于同一因果路径；Figma Dev Mode 值得学习的是同一设计对象为开发者切换到专用任务视图；Notion Projects 值得学习的是同一对象可按数据库、时间和依赖关系观察。这些原则不要求复制任何色值、字体或侧栏。

## 5. 高信息密度可以很高级

Carbon、Atlassian、Fluent、Ramp 和 Mercury 的成熟经验表明，密度不是廉价感的反义词。对齐、列宽、状态、语义间距和可扫描性比“大量留白”更重要。数据页面过度留白会拉长眼动路径，反而显得像未完成的线框稿。

## 6. 字体身份不是越罕见越好

成熟系统关注角色、层级、基线、行高、跨平台和数字特性。字体名本身不能证明设计判断。中文工具页面往往可以用一套稳定 UI 字体加数字特性完成身份；真正的识别度来自计算、证据、比较和反馈结构。

## 7. 同一数据需要多个视图时，先确认问题是否不同

Notion、Linear、Airtable 等产品说明了列表、时间线、关系和详情可以共享对象模型，但每个视图必须回答不同问题。为了“丰富”而平铺多种视图，只会增加界面噪声。

## 8. 进度必须导向下一步

Khan Academy、Duolingo 和 Brilliant 都把进度与下一次学习行动结合。仅显示百分比、连续天数或完成章节，不足以构成学习设计。专业学习站更应显示错误类型、判断链断点和应补强的练习。

## 9. 比较需要共享尺度

Carbon 表格、Ramp 方案比较和 Coursera 目录共同说明：比较任务需要对齐行、稳定列、清晰筛选和可解释差异。三张漂亮卡片通常会破坏共享尺度。

## 10. 可信感来自可追溯与可恢复

金融、公共服务、开发工具和审计类页面的可信感主要来自来源、状态、版本、错误说明、确认和撤销，而不是深蓝色、宋体或官方风格线条。

## 11. 动效应由事件类型决定

产品中的动效主要帮助理解状态与空间；营销中的动效可以承担叙事。把同一种 fade-up 或 hover 上浮应用到所有对象，既没有信息价值，也迅速形成模型指纹。

## 12. 无样式组件是行为保险，不是审美方案

Radix、Base UI 与 Ark UI 说明可以复用可访问行为而保留视觉自主。但一旦把社区最常见皮肤、间距和圆角原样交付，仍然会得到同脸页面。

## 13. 参考角色必须分清，但数量不应配额化

单一参考同时承担工作流、交互和表达，容易诱导整套复制。需要参考时，应先说明它承担工作流、交互、表达或反参考中的哪一种职责；一个参考只承担能够被真实证据支持的有限作用。局部任务可以不新增参考，明确的结构问题也可能只需要一个交互参考。角色分离用于防止复制，不是要求每个页面机械凑齐四项。

## 14. 参考研究必须留下“不可迁移”结论

只记录喜欢什么，会让模型抄得更快。每张观察卡必须同时写清楚哪些内容依赖原品牌、原技术、原受众和原业务，不能复制。拒绝什么和吸收什么同样重要。
