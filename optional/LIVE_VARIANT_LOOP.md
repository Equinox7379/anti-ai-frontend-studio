# 可选：轻量真实浏览器变体循环

完整的浏览器覆盖层、HMR 热交换、事件轮询和会话恢复系统投入较大。本包只吸收其核心机制：**在真实页面、同一状态和明确范围内比较变体，并让接受／丢弃成为验收动作。**

## 适用条件

- 页面方向和视觉世界已经成立；
- 用户明确指出一个目标，例如“这个结果区再有力一点”；
- 变体不会改变产品事实、主要流程或未命名区域。

## 流程

1. 固定目标元素、URL、数据、视口、状态和相邻区域。
2. 选择一个 `DESIGN_VERBS.md` 动词。
3. 保留原版，最多生成两个变体。
4. 每个变体只能改变批准的一个主维度，例如尺度／密度／空间；不顺手加入新字体、色彩、圆角和动效系统。
5. 在真实浏览器中热替换；环境不支持时，用完全相同状态截图并排。
6. 用户或设计负责人选择 `accept` 或 `discard`。
7. 接受后运行相关状态、响应式和精修验证；丢弃后删除临时代码。

## 变体记录

```text
TARGET =
VERB =
PRESERVE =
ALLOWED_AXIS =
VARIANT_A =
VARIANT_B =
ACCEPTED = original / A / B
WHY =
```

不要为所有页面建立常驻变体基础设施。只有重复、大量或多人协作的变体工作证明有需求时，才考虑完整 live 系统。
