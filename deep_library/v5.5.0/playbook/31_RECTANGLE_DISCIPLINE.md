# 矩形纪律：避免“安全但满屏方块”

## 为什么会发生

模型知道不能滥用圆角卡片后，常把圆角归零，再用白底、四边描边、阴影和固定 padding 重新画出一墙直角面板。视觉看似克制，本质仍是“先切盒子，再塞内容”。功能机制也可能被错误地实现为一排卡片。

## 什么算有界表面

一个内容区域同时拥有两项以上时，进入表面账本：独立背景、两边以上描边、圆角、阴影／玻璃、明显固定内边距、与内容流断开的固定宽高。原生输入、按钮、弹层和真正独立对象可以合理成盒；文字分组、解释、顺序、因果和辅助状态通常不需要。

## 边界升级顺序

只有前一层不足以表达关系时，才升级到下一层：

```text
内容顺序
→ 邻近与留白
→ 对齐与共享基线
→ 字号、字重和数字格式
→ 缩进、列表、表格与行内展开
→ 局部规则线或背景平面
→ 完整有界表面
→ 浮层与高程
```

“更整齐、现代、精致、这里需要变化”不是边界理由。大型表面至少应代表独立对象、独立状态／权限、可比较实体、受保护焦点的浮层，或边界对避免误读至关重要。

## 方块预算

标准／重大页面记录：

```text
PRIMARY_BOUNDED_SURFACE_COUNT = <首屏主要内容表面数量>
BOUNDARY_JOBS = <每个边界承担什么任务>
UNBOUNDED_GROUPING_METHODS = <使用了哪些无框分组方法>
REPEATED_BLOCKS_JUSTIFICATION = <重复对象为何必须重复成盒；没有则写 none>
```

自然控件不计入内容方块预算。首屏出现四个以上主要有界表面，或五个以上同型重复容器时，必须查看真实截图并执行下列测试；这不是绝对数量禁令，但不能只靠文档解释放行。

## 四个测试

1. **去皮肤**：移除背景、边框、圆角和阴影后，层级是否仍成立？
2. **轮廓**：眯眼或模糊后，先看到任务关系，还是一墙矩形？
3. **对象**：每个表面能否说出独立对象、状态、操作或防误读职责？
4. **合并**：相邻表面能否用空间、对齐、连续流、表格或行内展开合并？

## 合理例外

商品、文件、项目、可拖拽对象、独立记录、比较实体、弹层和拥有独立状态的对象可以重复成盒。此时重点检查卡片是否真的支持选择、比较、移动、状态或操作，而不是用卡片包装每一段说明。

## 税务底稿示例

错误：六个计算节点各做一个矩形，最终税额再做深色方块，底稿和依据分别做大卡片。

更好：计算式使用共享基线与操作符连续展开；底稿使用同一金额列；政策依据在当前调整项下就地展开；最终税额通过尺度与会计双线形成结论。关系保持完整，但矩形轮廓不再成为主角。
