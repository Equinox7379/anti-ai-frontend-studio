# 微交互与动效设计引擎

动效的输入是事件，不是风格。先列出用户事件，再决定是否需要运动。

| 事件 | 推荐反馈 | 起始时间范围 |
|---|---|---:|
| hover | 轻微对比或下划线变化 | 100–160ms |
| press | 立即压暗、位移或形变反馈 | 70–110ms |
| focus | 无延迟显示稳定焦点 | 0ms |
| disclosure | 保持空间来源的展开／收起 | 160–240ms |
| menu/popover | 从触发点建立空间关系 | 160–260ms |
| modal | 清楚建立新层级并管理焦点 | 200–320ms |
| save/calculation | 保留布局，显示进行中与结果 | 依据实际延迟 |
| validation error | 聚焦并解释错误 | 不使用抖动羞辱用户 |

时间只是起点，距离、平台和内容复杂度会改变最终值。页面级统一 fade-up、所有卡片 hover 上浮、所有按钮缩放和滚动劫持均不属于微交互。

## 因果完整性

动效必须从触发元素出发并回到可理解状态。Popover 的方向应与触发点一致；折叠后焦点不能丢失；快速重复操作应能中断旧动画并保持最终语义正确。

## 减少动态

`prefers-reduced-motion` 不是简单把 300ms 改成 100ms。装饰运动应取消，空间说明可改为即时切换或淡化，状态反馈必须保留。自动循环超过五秒时需要暂停或停止控制。

## 性能

优先动画 transform 与 opacity，避免读写布局交错和全局 `transition: all`。但不要为了“只动 transform”而把本来应该重新布局的内容缩放变形。性能与语义同样重要。
