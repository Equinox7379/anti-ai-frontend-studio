# 色彩、边界与材质设计引擎

## 色彩从来源产生

先记录真实来源，再选色值。来源可以是品牌资产、实际工作物、数据语义、使用环境或摄影素材。行业刻板印象不是来源：“金融用蓝、教育用绿、文化用米白”均无效。

## 四类颜色角色

| 角色 | 职责 |
|---|---|
| Canvas | 决定长时间观看的亮度与环境感 |
| Ink | 建立正文、标题和次要信息层级 |
| Action | 表示可交互和当前选择，不与成功状态混用 |
| Status | 成功、警告、错误、信息，不能只靠颜色传意 |

项目可以拥有更多 Token，但必须先通过这四类角色。颜色数量少不等于高级，颜色多也不必然廉价；关键是每种颜色是否有稳定语义。

## 表面选择器

边框用于表达边界与对齐；背景变化用于表达模式、范围或持续区域；阴影只在遮挡、浮层或真实高度关系中使用；圆角用于表达对象属性和触控感。不要为一个普通文本段落同时使用背景、边框、圆角和阴影。

## 线条层级

普通分组、可编辑边界、小计、最终合计和错误阻断不能都使用同一条 1px 灰线。线条应按语义建立层级，但不能把发丝线铺满页面来制造杂志感。会计双线只有在确实表达汇总关系时才成立。

## OKLCH 与对比

可以使用 OKLCH 生成同一色相的交互状态，但最终仍需在目标浏览器和真实背景上验证对比。相对颜色是工程工具，不是审美来源。低对比浅绿按钮配白字不会因为颜色柔和就变高级。

## 材质预算

一个页面原则上只保留一种主要材质语言。玻璃、纸张、金属、荧光、噪点、颗粒和模糊不应同时出现。材质必须与品牌或工作环境有关，并有低性能和减少透明度替代方案。
