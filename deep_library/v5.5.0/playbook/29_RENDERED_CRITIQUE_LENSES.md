# 渲染后批评镜头

优秀设计不能只在规范文字中成立。以下镜头应合并在少量截图轮次中完成，不要求每项都生成独立证据。

| 镜头 | 问题 | 适用范围 |
|---|---|---|
| 五秒测试 | 能否说出对象、核心关系、当前状态和下一步？ | 标准／重大改版 |
| 眯眼或模糊 | P0 是否先出现，还是所有内容一样重？ | 所有视觉改动 |
| 骨架测试 | 去掉文案与颜色后，结构仍表达任务吗？ | 信息架构变化 |
| 灰度测试 | 层级是否只靠色相？ | 使用多状态色时 |
| 数据测试 | 数字、小数、差异和单位能否快速比较？ | 财务／数据界面 |
| 动作移除 | 去掉按钮颜色后，位置与文案仍说明下一步吗？ | 操作流程 |
| 内容压力 | 长中文、空值、错误、极大数字会否破坏主张？ | 受影响内容 |
| 同状态前后 | 相同视口、数据、状态下改善了什么？ | 既有页面改造 |

## 批评顺序

1. 任务是否成立；
2. 构图是否有主张；
3. 领域机制是否真实；
4. 状态和错误是否连续；
5. 字体、间距、边界和动效是否精确；
6. 最后才判断是否还需要一处愉悦。

不要用“更现代”“更高级”“更有呼吸感”作为结论。批评必须指向可见关系，例如：最终结果与中间量字号仅差 2px，眯眼后无法形成结论峰值；或侧栏证据无法由具体调整项触发，因此只是常驻说明。
