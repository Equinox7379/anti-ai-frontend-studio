# 组件与状态设计引擎

组件不是一只容器，而是一个业务对象或动作的稳定表达。设计每个组件时填写五个问题：它是什么；当前处于什么状态；用户可以做什么；操作后发生什么；信息从哪里来。

## 常用组件的正向语法

| 组件 | 应表达什么 | 高级感来自哪里 |
|---|---|---|
| 导航 | 位置、范围和可到达目的地 | 清楚的层级、点击区和状态，不是彩色竖线 |
| 表格 | 同尺度比较与扫描 | 列宽、数字对齐、密度、冻结与汇总语义 |
| 表单 | 问题、输入要求、校验和后果 | 标签、帮助、错误邻近和稳定布局 |
| 折叠组 | 可延迟的信息与摘要 | 摘要中先给数量、状态或结果，不只写“展开” |
| 侧轨 | 持续上下文、证据或复核 | 与主工作区的可追溯关系，不是普通卡片 |
| 状态 | 结果、风险和下一步 | 文案、图形和颜色共同表达，不靠 Badge 墙 |
| 空状态 | 为什么为空以及可以做什么 | 具体行动，不默认插画和大按钮 |
| 操作 | 结果与风险层级 | 动词准确、主要操作唯一、破坏性路径可恢复 |

## 状态矩阵

重要组件至少设计 default、hover、focus-visible、active、selected、disabled、loading、success、error、empty 和 long-content。截图看不到的状态不能被算作完成。

## 卡片准入

内容只有在它是独立实体、拥有独立状态和操作、需要与同类比较、可以移动选择或边界对理解至关重要时，才适合成为卡片。直角面板也接受同一测试。不能通过取消圆角规避卡片泛滥。

## 操作层级

每个视口原则上只有一个主要动作。次要动作可以是描边、文字或菜单，但不能都拥有相同颜色和重量。不可用动作要明确说明触发条件；不要让可用按钮看起来像禁用状态。
