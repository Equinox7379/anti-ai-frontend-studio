# 中文字体与排版设计引擎

字体不是从排行榜中挑选，而是一次角色与指标匹配实验。工具站不需要靠展示字体证明高级；长文站也不需要自动使用宋体。

## 先定角色

| 角色 | 需要优化的指标 |
|---|---|
| UI | 小字号清晰、按钮与表单稳定、多个真实字重、标点自然 |
| Reading | 长时间阅读、段落灰度、行长、标点停顿、粗体差异 |
| Data | 等宽数字、小数点、负数括号、百分号、货币符号 |
| Display | 品牌识别、短标题、字符覆盖、跨平台一致性 |
| Identifier | 版本号、代码、路径、准则编号的字符辨识 |

项目可以让一套字体承担多个角色，但必须测试，不得因为“统一”而默认一体化。

## 候选不是字体名，而是字体类型

先确定候选类型，例如中性 UI 无衬线、人文无衬线、紧凑数据字体、正文宋体或项目品牌展示体。然后从合法来源中找具体候选。低能力模型没有外部证据时，只能使用中性草稿字体，不得自选展示体。

## 三组同版式实验

候选 A、B、C 必须在完全相同的内容、宽度、字号和间距下比较。禁止在偏爱的字体方案中顺便增加更大的标题和更宽的留白。比较内容至少包含中文标题、长段落、按钮、表格、金额、负数、英文标识、日期和错误信息。

## 必测样张

```text
货币缺乏可兑换性的判断顺序
审计证据的充分性与适当性
应纳税所得额 23,400,000.00 元
本期递延所得税负债为（1,280,450.75）元
借：长期股权投资  5,850,000.00
贷：银行存款      5,850,000.00
Policy-2025-A · IFRS 21 · CAS 19
“来源、性质、取得方式”不能被单独视为结论。
```

## 中文优先混排

中文主导页面先确定 CJK 字面高度、标点、行高和粗细，再配置拉丁与数字角色。不要让 Inter、Geist 或其他英文 starter font 位于中文字体之前并决定全站气质。

## 尺寸与行长

工具正文通常从 15–17px 测试，长文通常从 16–19px 测试；这只是实验起点。中文正文应结合实际字体测试行长和行高，不机械照搬英文 `65ch`。标题默认不使用极端负字距，小号标签也不通过大字距伪装英文 all-caps。

## 数据排版

金额列通常右对齐并测试 `tabular-nums`。若字体不支持比例数字特性，CSS 声明不会自动解决问题。汇总、负数、零值和缺失值必须在真实表格里比较。

## 字体决定的放行条件

字体理由必须说清它改善了什么任务或指标。字体体系真实发生变化时，至少用同版式基线与候选作对照；只有候选差异难以判断、展示字体风险较高或用户明确指出字体同质化时，才扩展到三组。验证主字体未加载时的布局，确认许可、体积和目标平台。跨项目字体比较仅在建立新视觉语言、连续项目重复同一字体，或用户明确指出“全世界 AI 都在用这种字体”时启用；比较一到三个能够取得的近期无关项目，不为凑数制造材料。仅写“更高级、书卷气、现代、专业”直接退回。
