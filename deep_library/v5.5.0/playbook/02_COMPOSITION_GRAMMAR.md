# 构图语法：让模型知道如何把内容放好

## 六种基础区域

| 区域 | 作用 | 常见位置 | 设计要求 |
|---|---|---|---|
| Context | 当前对象、项目、章节、年度或模式 | 顶部或窄侧栏 | 稳定、低干扰、与 P0 邻近 |
| Work | 主要输入、阅读、计算或编辑 | 页面最大区域 | 占据主要宽度与注意力 |
| Evidence | 来源、复核、解释、帮助 | 右轨、底部或按需层 | 可追溯，不抢主任务 |
| Result | 结果、结论、状态和下一步 | 与 Work 相邻 | 必须清晰区分中间值与最终值 |
| Navigation | 跨页面或层级移动 | 顶部、侧边、页内目录 | 只保留完成任务必要的层级 |
| Transient | 弹层、提示、临时比较 | Overlay 或局部展开 | 不应永久占据主工作区 |

## 构图句法

“主工作区＋证据轨”适用于计算、审核和编辑；“文档＋边注”适用于长篇解释但不适合复杂表单；“对齐矩阵”适用于方案或项目比较；“单路径工作流”适用于高风险多步骤任务；“对象列表＋详情”适用于集合浏览；“案例事实＋判断链＋反馈”适用于职业判断训练。

这些不是现成模板。每种句法必须根据真实对象、关系和状态重写。若同一句法连续用于多个无关项目，必须改变信息顺序或交互方式。

## 宽度与阅读

主工作区应获得足够宽度完成任务。数据表不应被塞进窄卡片；连续中文正文需要控制行长；双侧栏只有在两个侧栏都必须持续可见时才成立。1024px 下，如果导航和目录占去接近一半宽度，而正文才是主任务，应当收起或合并导航。

## 对齐网络

每个页面建立少量强对齐线。标题、正文、表头、金额、小数点、按钮和辅助说明应各自归入明确对齐网络。元素的数学中心不等于视觉中心，图标、中文标点和不同字重需要小范围光学校正。

## 密度梯度

入口可以舒展，数据区可以紧凑，判断区需要集中，章节转换需要停顿。不要让所有区域都使用同样的 padding 和 gap。相同语义使用相同距离，不同语义必须有可感知差异。

## 方向数量按不确定性决定

已有方向明确或仅做局部修正时，一套已批准方案即可。存在真实结构取舍时比较两套；多页面或设计语言级改造通常比较两到三套。操作型、解释型和比较型是候选视角，不是必须凑齐的固定模板。所有方向都应使用真实内容，并写出它不擅长的场景。
