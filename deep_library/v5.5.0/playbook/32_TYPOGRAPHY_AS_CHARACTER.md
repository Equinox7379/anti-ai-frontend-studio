# 排版本身就是信息：字体作为性格，而不是默认搭配

字体不是给页面换气质的滤镜。字形、字号、字重、字宽、字距、行高、数字特性、换行和结构装置共同决定用户如何识别对象、关系、状态和阅读顺序。

## 结构装置必须编码内容

- `01 / 02 / 03` 只用于真实流程、时间轴、优先级、审计步骤或章节定位；交换顺序不影响理解时，编号通常只是装饰。
- 分割线只区分表格行、汇总层级、来源、章节或状态；能用空间表达时不再加线。
- 眉题只提供标题不能承担的真实上下文，例如法定状态、文档类型或对象类别；“Overview”“Insights”“本节内容”一类填空眉题应删除。
- 角标、标签和徽章必须表示稳定状态或类别，不能为了填空出现。

## 先判断界面模式

- `operate／read`：稳定扫描、中文可读、数字比较和长时间使用优先；一个经调校的 CJK-first 家族往往足够。
- `persuade／experience`：展示字可以承担品牌声音，但必须被 Brief、真实内容或既有资产证明。

产品工作台不因“需要作品感”自动增加展示衬线。

## 高风险默认

`Inter + Playfair Display`、`Inter + Instrument Serif`、系统无衬线＋任意高反差衬线，都是常见生成式捷径。不是永久禁用，但使用时必须回答：

- 展示角色完成什么真实任务？
- 为什么正文家族不能通过字重、字宽、尺度和间距完成？
- 中文、英文、数字与标点混排是否统一？
- 与最近项目是否再次重复？

## 字形如何形成性格

性格可以来自字面宽窄、笔画开口与端点、字重跨度、数字造型、可变字宽／光学尺寸、标题换行、中文与拉丁比例、字距和行距。展示角色若存在，必须记录实际字重、字宽、字距、行高和使用范围；只换一个少见字体名不算设计。

正文必须在真实中文、标点、按钮、长段落、英文版本号和目标字号下验证。数据角色必须验证等宽数字、小数点、负数括号、百分号和单位。等宽字不能作为“技术感”服装。

## CJK-first 与同版式试验

先确定中文字面高度、标点、粗细、换行和行距，再配置 Latin 与数字角色。候选字体必须放入完全相同的结构、字号、宽度与内容中比较；不能给偏爱的方案额外留白或更大字号。

## 记忆点边界

字体可以成为唯一 Signature，但不能同时再让强颜色、巨型方块、插画和复杂动效争夺人格。若页面最有价值的机制是计算链、证据路径或比较矩阵，字体应支持它，而不是强行成为主角。
