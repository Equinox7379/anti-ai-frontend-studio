# 从 Anti-Slop 到 Excellence：增量研究结论

## 本轮问题

v5.4.2 已能减少紫色渐变、圆角卡片墙、奶油宋体编辑式页面和施工者自由重选方向，但真实税务页面显示：模型可能通过“把所有高风险材料删掉”获得一个安全、整齐、毫无主张的结果。反模板规则建立的是下限，不是优秀作品的生成机制。

## 研究来源与采纳边界

### Anthropic Frontend Design

来源：https://github.com/anthropics/skills/tree/main/skills/frontend-design

采纳：从主题自身的材料、对象和语言出发；结构装置必须编码真实内容；先计划、再批评、再施工；大胆预算集中在一处。

不采纳：把“独特字体＋一处审美风险”机械设为所有产品 UI 的必需项。工具界面的记忆点更适合来自功能关系。

### Impeccable

来源：https://github.com/pbakaus/impeccable

采纳：`bolder` 不等于增加效果，而是把已有系统最强的机制做完整，并让周围安静；`polish` 不能偷渡重设计；检测器发现缺陷不等于证明质量；一个轴一个 Pass。

不采纳：二十余命令、全局审美体系、固定字体禁用表和确定性审美总分。

### UI Craft

来源：https://github.com/educlopez/ui-craft

采纳：渐进使用层级、设计记忆、聚焦命令、只读审查和完成度验收线。

不采纳：Minimal／Editorial／Dense Dashboard 固定风格变体及将设计质量压缩为单一分数。

### Google DESIGN.md

来源：https://github.com/google-labs-code/design.md

采纳：机器可读 Token 与人类理由并存、差异检查和持久设计事实。

不采纳：为现有包增加第二份竞争合同；v5.5 继续以 DESIGN_SPEC 5.4.0 为唯一正式规范，Excellence Note 只是按需附录。

### UI UX Pro Max

来源：https://github.com/nextlevelbuilder/ui-ux-pro-max-skill

采纳：最小检索模式、单一主意图、显式领域、结果失配时只做一次窄化重试、零结果不得伪造。

不采纳：自动把产品类型映射到完整风格、配色和字体组合。

### Taste Skill

来源：https://github.com/Leonxlnx/taste-skill

采纳：先读 Brief、改版先审计已有资产、规则必须有语境。

不采纳：固定 variance／motion／density 默认值、固定技术栈与字体池；其主要范围仍限定在营销页、作品集和表达型改版。

### Agent Vision Toolkit

来源：https://github.com/Anionex/agent-vision-toolkit

采纳：视觉观察必须携带当前任务意图；既有页面使用同一视口、数据与状态做前后核对。

不采纳：将外部视觉 API 变成默认依赖，或未经授权上传私有截图。

### 人因与成熟产品规范

- Nielsen Norman Group：尺度、视觉层级、平衡、对比与 Gestalt 必须帮助用户识别重要性；眯眼测试可以发现注意力分配问题。
- Tuch 等：低视觉复杂度与高类别典型性通常更受欢迎，说明优秀产品不应为了独特破坏熟悉框架。
- Miniukovich 与 Figl：类别典型性显著影响可信度，尤其适合税务、金融和企业工具。
- Reinecke 等：视觉复杂度和色彩偏好受到受众与文化影响，不存在跨项目通用的“最佳颜色量”。
- SAP Fiori Object Page：页头只保留关键上下文，主要动作有明确优先级，侧内容只承载与主内容联动的上下文。
- Carbon Data Table：数据比较应获得足够的主工作区空间，不应被塞进狭窄容器。
- Stripe Tax：计算结果同时提供税务适用原因和按辖区／产品拆解，支持“结果必须解释”的设计方向。

## v5.5 的综合模型

```text
熟悉框架        保护信任和可学性
功能性焦点      让领域关系可见、可操作
构图对比预算    防止所有内容同样平或同样吵
精工验收        让方向在真实状态和设备上成立
克制愉悦        仅在不干扰任务时加入
```

这不是新的视觉风格。税务页可以使用计算脊柱，审计页可以使用证据链，驾考页可以使用空间路径，学习页可以使用错误断点；它们共享方法，但不会共享皮肤。
