执行摘要：先说结论

一句话结论

你的包管不住 GPT，不是规则写得不够多，而是规则多到模型根本执行不了；更根本的是，这个包把力气花在了"流程完备"而不是"界面好看"上，而负面禁令清单只能约束模型的"审查行为"，管不住"生成行为"。解药不是第 8 轮迭代，而是：把 120 个文件换成 1 页"设计宪法"，每次生成喂真实参考样本，每次人工修改后把修改点回写成新规则。

02

根因诊断：为什么 120 个文件管不住一个对话

搜索员A、搜索员B、搜索员C 与搜索规划师四方独立分析得出同一组结论，以下为去重合并后的 5 个根因。

根因 1指令过载：注意力被稀释

包内 24 个 playbook、17 个工具、17 篇研究、12 个模板、11 个测试、7 个治理文件，约 2,900 行文档、353 条语料规则互相引用。而单次对话中 LLM 能稳定执行的高权重规则通常只有 10–20 条。四项独立研究支撑：

来源结论
OpenAI 开发者社区高赞讨论《Prompt Anti-Patterns — When More Instructions May Harm Model Performance》（2026-01，已抓取核验）向 system prompt 叠加多条指令，即使单条都有用，整体表现反而下降——注意力从"深度推理"转移到"表面合规"
mlops.community《The Impact of Prompt Bloat on LLM Output Quality》（2025-07）输入变长即劣化输出（远未到上下文上限时已发生）；且"语义相关但与任务无关"的干扰伤害最大——2,900 行设计论述正是理论上的最毒干扰类型
Liu et al.《Lost in the Middle》（Stanford, 2023）长上下文中部信息利用率最低——排在第 10 个文件之后的核心规则（如反模式注册表）基本等于没写
Harada《Curse of Instructions: LLMs Cannot Follow Multiple Instructions》（OpenReview，被引 8，已抓取核验）指令数量越多，模型对每条指令的遵循率越低——塞进 120 个文件的包，只能收获"全面服从的幻觉"

根因 2流程错配：包为"多角色流水线"设计，你是"单人单对话"

包的默认工作流是"云端设计 AI → 批准 DESIGN_SPEC.json → 本地施工 AI 落盘 → 云端审核 AI 按 HARD_GATES 裁决"，依赖 reference_pack.py、design_spec_lint.py 等 Python 工具链和多会话角色协作。但你的真实场景是网页版 ChatGPT 里一个人直接要页面：没有持久文件系统、没有 Python 执行环境、没有多会话协作。流程载体根本不存在，模型抓不住重点，只能回退到先验审美——工具全废，只剩零散禁令印象，"遵守全看心情"。

根因 3重"流程完备"，轻"输出质量"：七轮迭代零验收

ITERATION_LEDGER.md（v4 → v5.4 七轮记录）逐轮内容如下——没有任何一轮的验收标准是"产出界面变好看了"：

轮次迭代内容性质
第 1 轮登记 295 个获奖站点目录语料元工作
第 2–3 轮深读 54 → 66 个设计系统文档语料元工作

这是 LLM 自我改进的典型陷阱：它擅长无限递归地完善"规则体系"，但规则体系的质量和它生成界面的质量是两回事。第 7 轮包自己都承认"固定三套方向、3+1 参考、全状态/全视口证据会把视觉工作扩张为流程工程"——给出的解法却仍是加更多机制（角色分离、治理文件），而不是砍掉机制。

根因 4纯负面禁令触发"粉红大象"效应——还会制造"规则腔"

心理语言学中的"反讽进程理论"（Ironic Process Theory）在 LLM 上同样成立：要回避某物，必须先在注意力里激活它。你越写"不要紫色渐变"，生成时紫色渐变在注意力里越活跃。这不是猜想——《纽约客》2026 年 6 月 Kyle Chayka 的报道引述 Anthropic 自己的承认：给 Claude Design 一句 "don't use cream" 式的通用负面指令，只会让模型转向另一个固定色板，而不是产生真正的多样性；Anthropic 官方提示工程文档的建议恰恰相反："告诉模型该做什么，而不是不该做什么。"（16x Eval 对此"粉红大象问题"有专文分析，均已抓取核验）

你的两代经历正是这个机理的实录：第一代 AI 味（紫渐变 SaaS 风）被禁之后，模型并没有获得多样性，而是收敛到了第二代 AI 味（奶油底 + 墨绿 + 编辑风）——包列了 C01–C10 十个"要避开"的簇，等于把所有固定色板在注意力里过了一遍。此外，中文去 AI 味社区的实测（Riven《去 AI 味怎么做才有效》，rar.design，2026-07）发现规则堆多后产出还会出现"规则腔"：为了避开所有禁止句而写出来的东西，工整得像在填表——那是新的 AI 味。你的截图恰好证明了这一点：禁令确实起效了（没有紫渐变、没有玻璃拟态），但骨架层的 AI 味更密集、更难察觉（§3.2 逐项拆解）。

根因 5AI 教 AI 反 AI 的自我指涉悖论

LLM 的本质是输出训练数据的统计平均值，独特设计生活在分布的尾部，而模型系统性地丢失尾部（alexlavaee 技术复盘；Nature 2024 年关于模型在生成数据上训练发生"分布坍缩"的研究亦印证此点）。GPT 写这个包时，它对"AI 味"的理解只能来自表层特征归纳（紫渐变、Inter、玻璃拟态…）；而它实际生成界面时的 AI 味藏在骨架层：布局语法、信息密度节奏、容器化习惯、文案腔调。所以包防得住皮肤、防不住骨架——这也解释了你最困惑的一点："做这个包的 AI 自己还会生成 AI 味很重的前端。"

03

机理：AI 味到底从哪里来

§3.1四个来源（truematter 让 Claude 自答"为什么 AI 界面都长一样"的实录）

来源机理对策方向
统计平均（众数审美）模型永远预测"最安全"的下一个 token，产出趋向训练分布的平均值用"具体的你"替换"平均"：精确数值 + 真实样本
组件库锁定AI 原型工具默认 Tailwind + shadcn/ui + Inter，库自带强烈视觉观点，模型极少偏离默认值钉死 token；本地开发可直接让默认色板 build 报错
"合格中位数"问题AI 擅长"看起来不出错"，但"不出错"与"有个性"几乎对立——有个性要冒"可能难看"的风险风格实验多方案并行，人眼挑（§4 第 3 步）
缺失真实意图人类设计师的选择来自品牌、情感、语境或私人品味；模型没有观点，会把一切平均成乏味共识先 PRFAQ 想清楚，再把意图写进任务描述

04

替代工作流：六步走

核心思想一句话（反AI味社区共识）：AI 味的反面不是"人味"，是"具体"。把所有抽象形容词（高级、专业、书卷气、不像 AI）替换成具体数值、具体样本、具体参照物。

1

用"一页设计宪法"替换 120 个文件的包

维护一个 1–2 屏能装下的 DESIGN.md，常驻在 ChatGPT 的项目指令/自定义指令里（比每次贴 zip 强得多）。内容必须全部是可执行数值（色值、字阶、圆角 px），硬禁令数量为 0——一律改写为可检测的正向数值锁定（v2 修订：v1 实测含 11–14 条"禁止"类条款且自相矛盾，已按外部评审意见整体重写）；行为类负面清单移入人工自检（§5.4 / 附录A），不进模型指令。完整文本见 §5.1。

为什么有效：styles.gallery 的结论——把 token 钉死成数值，模型就没有"退回平均值"的空间。工程强化（本地开发时）：stylelint / Tailwind 配置里把默认色板设为非法值，让"退回默认"直接 build 失败——唯一不依赖模型自觉的强制层

2

喂真实参考样本，不给形容词

模型从样本萃取模式的能力 ≫ 理解形容词的能力。每次生成前给 2–3 张你认可的真实产品截图，并说清"学什么"："信息密度像截图 A 的表格区，导航像截图 B，配色遵守宪法第 2 节"。财税场景推荐参考：税局申报系统的表格结构、Stripe Dashboard 的数据排版、Ramp / Mercury / Wise 的工具质感——只取局部，不要求整体像谁（整体模仿会带来新的同质化）。

进阶技法：F12 → 点页面里色彩最鲜明的按钮 → 只复制那个主题 CSS 变量文件发给 GPT比截图（丢失 hover/动效/精确色值）和整页代码（浪费 token、稀释上下文）都好。

先想清楚，再拆开生成（禁止 one-shot 出全页）

反馈回写——整个体系里最值钱的一步

每次你手工修改 GPT 的产出后，把修改点喂回给它："刚才我改了这 3 处：①去掉了卡片边条 ②徽章换成普通文字 ③表格字号 14→15。请把这 3 条归纳成候选条款（含数值与判定方式），回写设计宪法——按元规则 E1：每新增 1 条，必须合并或淘汰 1 条旧条款，A–D 层条款总数 ≤20，防止宪法膨胀回根因 1。"你的每次手工修改都是一条"AI 以为对、但你觉得不对"的高价值数据。第一周你可能每次改 10 处，一个月后降到 2–3 处——那时宪法就长成了"只有你才有的设计指纹"。

世界上最好的反AI味规则没法下载，只能这样累积。你的包的问题正是它是"生成来的静态物"，没有你的校稿数据喂进去。

§5.1系统级"设计宪法"（放进 ChatGPT 项目指令 / 自定义指令，替代整个 zip 包）

你是一名资深产品界面设计师，负责为「财税核算工具」设计界面。以下是设计宪法 v2，全部条款由可判定的数值与正向要求构成；条款冲突按各层标注的优先级裁决，与宪法冲突的旧习惯一律作废。

【A · 排版层｜优先级最高，数值跨项目通用】
A1 字阶只允许 12 / 14 / 15 / 16 / 20 / 28 / 40px 共 7 档；正文固定 15px。
A2 行高分档：≥28px 文字行高 1.2；20px 行高 1.4；≤16px 行高 1.7。
A3 字距分档：≥28px 文字 letter-spacing 取 -0.01em ~ -0.03em（光学校准）；≤16px 文字一律 0，短大写标签的适度加宽除外（+0.025em ~ +0.12em，对应自检 T2/#29 口径）。
A4 正文段落区行宽 34–45 个中文字符；表格区不设行宽限制。
A5 全部数字（表格、合计、日期、进度）使用等宽数字：font-variant-numeric: tabular-nums。
A6 同一视口内字号档位 ≤4 种；最大字号 ÷ 最小正文字号 ≥2.5（工具型界面取值；营销页建议 ≥3）。

【B · 布局层｜数值硬约束】
B1 信息优先用表格、列表、分隔线承载；容器嵌套最多 1 层（面板内不再放卡片）。发丝分隔线与序号步骤为合法结构元素——C02 反模式指"奶油底+衬线+低饱和绿+发丝线+01编号+零圆角"整包仿静奢，单品不连坐；序号仅用于真实操作序列，解释性卡片不得贴序号标签（D2）。分隔方式须多样化且有语义：同一数据区块内分隔手段 ≥2 种（粗线 / 细线 / 留白 / 背景色差 / 缩进）；连续细线密度 ≤ 每 4 行数据 1 条，分组线与区块边界线线宽分档（分组 1px、区块边界 2px），禁止全行统一 1px 铺满；合计行用背景色差承载，不加线。
B2 间距只允许 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px；同一内容组内相邻间距 ≤8px，不同组之间 ≥24px（组内密、组间疏）。
B3 每页至少一处密度对比：一个区块间距用足下限（4–8px），一个区块留白用足上限（48–64px），两者同在首屏可见。
B4 每页至少一处非模板结构：非对称分栏 / 跨列表头 / 行内展开 / 无容器直排内容，四选一。

【C · 组件与色彩层｜数值锁定，本层随项目整体更换】
说明：以下为示例起点。开工前的"默认值供述"环节必须逐项确认或替换本层全部数值；替换后本层整体生效。正式项目不得沿用示例色板——示例色板（奶油底+低饱和绿）本身处于第 3 代"假高级编辑式"风格边缘，仅作占位演示。
C1 色板 6 色：背景 #FAFAF7、表面 #FFFFFF、主文字 #1A2E22、次文字 #5C6B62、边框 #E2E5DF、强调 #0D5C3F。启用水线：次文字对背景对比度实测 ≥4.5:1（示例值实测 5.38:1）；强调色每屏 ≤3 次；字体固定两族：标题思源黑体 Bold、数字与代码 IBM Plex Sans。
C2 圆角两个档位：控件 4px、容器 12px；胶囊形仅用于标签与按钮。全站圆角值 ∈ {4px, 12px, 9999px}。
C3 立体感只用一样：边框。浅阴影至多 1 处且限于浮层（0 1px 2px rgba(0,0,0,.05) 级）；同一元素上阴影与粗边框二选一。
C4 深色模式重新生成而非反色：背景 #0F1512–#141414，正文 #E5E5E5，强调色降饱和 10–20%，用 1px 边框替代阴影。
C5 图标一律线性图标库（如 Lucide），尺寸 16 / 20px 两档。
C6 动效：过渡仅限 opacity 与 transform，duration 单档 ≤200ms；同一屏内带入场动画的元素 ≤1 个；全部动画必须包裹 prefers-reduced-motion 判定。

【D · 内容姿态层】
D1 界面只显示与用户当前任务直接相关的状态；过程性确认（"已保存""已关联"）进单一状态栏或可折叠日志，不占用主版面。
D2 解释性内容默认折叠，点"查看依据"才展开；首屏只保留任务本体。
D3 按钮与链接一律动词短语开头（查看 / 核对 / 导出 / 调整），描述用户要做的事。
D4 占位数据用本领域真实格式的样例（真实税目名格式、真实金额格式）。

【E · 元规则】
E1 A–D 层条款合计 ≤20（当前 20 条）；每新增 1 条必须合并或淘汰 1 条旧条款，回写时输出变更日志"新增 X / 合并 Y / 淘汰 Z"。表述纪律：新条款一律正向数值式，硬禁令恒为 0；正文超 1500 字时，下一轮回写先合并压缩、后增补。
E2 每条条款必须含数值或可判定检查方式；写不出判定方式的提案不收入。
E3 冲突裁决：A > B > C > D；同层内冲突或宪法未覆盖的情形，停下来问我，不得自行取舍。

【工作方式】
- 我给出内容需求后，你先输出该页的信息层级（什么最重要→什么最次要），经我确认后再写代码。
- 开工前先输出默认值供述表（主色/背景/字体栈/圆角/阴影/间距刻度/布局骨架），我逐项确认或替换后才允许写代码；C 层项目化替换在此环节完成。
- 一次只做一个区块；每完成一个区块停下来等我人工修改反馈。
- 我每次给修改意见时，你把修改点归纳成候选条款（含数值与判定方式），输出"设计宪法 v(n+1) + 变更日志"，遵守 E1 等量交换。
- 全部样式值引用宪法数值；宪法未覆盖的值，先问我再写。
- 交付自检的对照物是渲染后的产出页面，不是设计意图陈述；逐条对照产出物判定。
使用说明（v2）：五层中 C 组件色彩层是"每项目可换层"——开工前的"默认值供述"环节必须完成 C 层项目化替换（示例色板本身处于第 3 代"假高级编辑式"边缘，正式项目应换成有品牌出处的色板；并行搜索员C 补证：用户 18:39 的 GPT 新产出即"墨绿+米白"，与示例色板同族、亦与本报告 §3.1 记录的"第二代收敛方向"同频——此自警非理论推演）；A / B 层数值跨项目通用。行为类负面清单（承诺式文案、自我表扬徽章、占位词黑名单）已全部移出模型指令，只在 §5.4 人工自检与附录A 60 条中使用——防"粉红大象"效应（根因 4）。② 每个新页面开一个新对话——长对话里指令遵循会持续衰减。v1 → v2 全部变更见《勘误与修订说明》。
