# 综合两条通道并修改真实作品

现在 A、B 均已完成。不要简单拼接报告。

## 1. 综合矩阵

```text
A 与 B 一致：
A 发现、B 无法检测：
B 发现、A 漏看：
B 的假阳性或合理例外：
仍无法验证：
```

A 通道对设计特异性、层级、情绪和任务负责；B 通道对源码信号、几何、状态和实现事实负责。任何一方都不能取代另一方。

## 2. 修正优先级

```text
任务受阻、数据或状态误导
→ 信息架构与主关系
→ 层级、密度和响应式
→ 字体、表面、颜色与动效
→ 光学和代码精修
```

只处理真实问题。检测器提示但经页面语义证明合理的内容，不必为了清零而删除。

## 3. 实际修改

至少对最重要问题修改代码并重新渲染。记录：

```text
PRIORITY_PROBLEM =
ROOT_CAUSE =
CODE_CHANGE =
RENDERED_RESULT =
PRESERVED_STRENGTH =
```

若第一稿确实成立，不强造修改；但必须给出真实路径和渲染证据，而不是一句“全部通过”。

## 4. 结论

不得产生生成者自签的设计分。最终说明应区分：已证实、合理推测、检测线索、假阳性和未验证项。
