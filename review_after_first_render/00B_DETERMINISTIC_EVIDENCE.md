# B 通道：确定性检测与浏览器证据

本通道在 A 通道记录完成后执行。它只回答“源码或页面中实际出现了什么”，不回答“这个设计好不好”。

## 1. 静态检测

```bash
node tools/slop_detector.mjs <实际前端源码目录>
node tools/slop_detector.mjs <实际前端源码目录> --json
```

检测器是零依赖、描述性工具。它可能提示：`transition: all`、渐变文字、常见默认字体配对、占位文案、三等宽网格、大圆角、彩色发光、装饰编号，以及多项信号共同形成的高风险配方。

## 2. 浏览器事实

按任务需要检查：

- computed font、字号、字重、行高和数字特性；
- 主要有界表面的数量与职责；
- 横向溢出、触控区、焦点、loading／error／empty；
- 真实视口中的换行、密度和布局顺序；
- 相同状态的修改前后截图。

## 3. 结果格式

```text
DETECTOR_FINDINGS =
BROWSER_FACTS =
POSSIBLE_FALSE_POSITIVES =
UNAVAILABLE_EVIDENCE =
```

每项必须包含文件／选择器／视口等定位。单个颜色、字体、圆角或网格不能自动定罪；组合信号仍需回到业务语义判断。

## 4. 禁止

- 不输出总分；
- 不把零命中称为“无 AI 味”；
- 不因低置信提示自动改设计；
- 不让检测结果覆盖 A 通道的初始观察；
- 不用私有类名替代用户可见事实。
